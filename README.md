# API-тесты сервиса «Яндекс Самокат»

Проект автоматизированного тестирования REST API учебного сервиса «Яндекс Самокат».

Тестовый набор покрывает основные сценарии API и демонстрирует работу с Pytest, Requests, параметризацией, фикстурами и Allure.

## Что протестировано

### Курьер
- создание нового курьера;
- проверка обязательных полей;
- запрет создания дубликата;
- авторизация курьера;
- негативные сценарии авторизации;
- удаление курьера.

### Заказы
- создание заказа с цветом BLACK;
- создание заказа с цветом GREY;
- создание заказа с двумя цветами;
- создание заказа без указания цвета;
- получение списка заказов;
- принятие заказа курьером;
- получение заказа по трек-номеру.

Позитивные и негативные сценарии проверяют HTTP-статусы и содержимое ответа.

## Стек

- Python 3
- Pytest
- Requests
- Allure

## Структура проекта

```text
.
├── tests/              # тестовые сценарии
├── api_methods.py      # методы для работы с API
├── conftest.py         # фикстуры и подготовка тестовых данных
├── data.py             # тестовые данные
├── helpers.py          # генерация данных
├── urls.py             # URL и эндпоинты API
├── allure_results/     # результаты последнего прогона Allure
├── pytest.ini          # настройки Pytest
└── requirements.txt    # зависимости проекта
```

## Подход к тестированию

- тесты сгруппированы по проверяемым эндпоинтам;
- HTTP-запросы вынесены из тестов в отдельный слой `api_methods.py`;
- действия с API размечены шагами `allure.step`;
- варианты создания заказа проверяются через параметризацию;
- для тестов генерируются уникальные данные курьеров;
- подготовка и очистка тестовых сущностей выполняются через фикстуры;
- тесты не зависят от результатов выполнения других тестов.

## Установка

```bash
pip install -r requirements.txt
```

## Запуск тестов

```bash
pytest tests -v --alluredir=allure_results
```

## Просмотр отчёта Allure

При установленном Allure:

```bash
allure serve allure_results
```

## Особенности тестового стенда

На текущем тестовом стенде зафиксированы два расхождения с ожидаемым поведением API:

- удаление курьера без идентификатора: ожидается HTTP 400, стенд возвращает HTTP 404;
- авторизация без одного из обязательных полей: ожидается HTTP 400, стенд возвращает HTTP 504.

Ожидаемые результаты в тестах сохранены в соответствии с требованиями API, поэтому эти проверки могут завершаться ошибкой на текущем стенде.
